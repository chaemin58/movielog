# 6주차 구현 및 제출 메모

## 구현

- 마이 탭 → 회원가입: 닉네임/이메일 형식 검증, v5 중복 확인, 비밀번호 형식 검증, 필수 약관 동의.
- 중복 확인: 확인 전/통신 중/사용 가능/중복/통신 오류 상태를 필드별로 관리.
- 입력 변경 시 이전 응답 무효화, 마지막 중복 문자열 재입력 시 요청 없이 에러 복원.
- 가입하기는 두 중복 확인과 입력 검증, 필수 약관 동의를 완료하면 홈으로 이동. 회원가입 POST는 보내지 않음.
- 로그인 링크는 준비 중 안내를 표시하며 실제 로그인은 구현하지 않음.
- 마이 탭 → 버튼 너비 비교: 같은 문구로 null / double.infinity / 160px를 한 화면에 표시.
- 공용 MovieLogButton: 기본/회색 비활성/로딩 상태. 입력 옆은 내용 너비, 가입하기는 전체 너비, 평점 다시 조회는 120px.
- 마이 탭 → 내가 등록한 평점: 학습용 memberId 1 조회. 로딩/빈 목록/오류/성공, 재조회 지원.
- 평점 상세 화면은 root Navigator로 열어 하단 탭을 숨기고 뒤로가기로 마이 탭 복귀.
- TMDB 제목·포스터 결합. 같은 영화는 한 번 조회하며 영화 정보 오류가 나도 평점은 유지.
- 워크북 Dio와 TMDB Dio 분리. 워크북 서비스끼리는 클라이언트 공유.

## 실행

기존 `.local.env`에 TMDB_ACCESS_TOKEN을 설정한 뒤 `flutter run`으로 실행합니다.
앱은 기존처럼 홈에서 시작합니다. 회원가입과 평점 목록은 하단 마이 탭에서 접근합니다.

- 실제 `GET https://workbook.devnoco.com/v5/members/1/ratings`: HTTP 200, 평점 3건 확인 (2026-11-03).
- 테스트는 실제 서버 상태를 변경하지 않도록 테스트용 서비스를 주입합니다.

- 자동 검증: nullable comment, Loading/Empty/Success/Error, 영화 정보 실패 시 평점 유지, 400/404 오류 문구, 버튼 너비와 클릭 차단, 평점 화면 진입·뒤로가기와 하단 탭 숨김.

## 직접 캡처할 항목

자동 테스트 통과와 실제 기기 수동 검증은 다릅니다. 아래 캡처와 PR 링크는 아직 준비되지 않았습니다.

- [ ] 닉네임·이메일 확인 전/통신 중/가능/중복 화면
- [ ] 입력 변경으로 확인 결과가 사라지는 영상
- [ ] 중복 문자열 재입력 시 즉시 에러가 복원되는 영상
- [ ] 버튼 너비 비교 화면에서 내용 너비/전체 너비/160px 비교
- [ ] 평점 Loading/Empty/Error/Success 화면
- [ ] PR 링크

학습용 회원 1에 실제 평점이 있으므로 Empty/Error는 테스트용 서비스 또는 네트워크 실패로 검증해야 합니다. 빈 목록을 만들기 위해 서버 데이터를 수정하지 않습니다.

## 트러블슈팅 메모

평점 화면에 들어가면 Provider를 찾을 수 없다는 오류가 났습니다. 앱 클래스가 두 곳에 있어서 서비스를 추가하지 않은 쪽이 실행되고 있었습니다. main.dart의 중복 클래스를 지우고 app/movie_log_app.dart를 연결해서 해결했습니다.

입력 A의 중복 확인 요청이 끝나기 전에 B를 입력하면 A의 결과가 B를 덮어쓸 수 있습니다. 각 필드마다 요청 버전을 두고 입력 변경 시 증가시켜 오래된 응답을 무시했습니다. 마지막 중복 값은 별도로 저장해 같은 문자열을 다시 입력했을 때 API 호출 없이 에러를 복원했습니다.

TMDB 조회 실패를 평점 조회 실패로 취급하면 유효한 후기가 사라집니다. 평점과 영화 정보를 분리하고 영화 조회 오류는 제목·포스터 placeholder로 처리했습니다. 일시적인 영화 조회 실패는 캐시하지 않아 다시 조회할 수 있습니다.
