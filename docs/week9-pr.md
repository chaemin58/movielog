# [Week 9] 즐겨찾기 연동, 영화 검색과 페이지네이션 구현

## 변경 내용

워크북의 Guided Practice와 Required Mission A~D를 구현했습니다. 영화 상세의 mock 북마크를 서버 상태와 연결하고, 마이페이지에서 내 즐겨찾기를 열어 상세에서 해제한 영화가 복귀 후 사라지도록 했습니다.

- MovieLog 로그인·회원가입·중복 확인을 포함한 API 경로를 `/v8`로 통일했습니다.
- 즐겨찾기 목록과 TMDB 영화를 `movieId`로 결합합니다. 빈 목록·목록 오류·카드 일부 실패를 구분하고 최대 5개 동시 조회와 카드별 재시도를 제공합니다.
- 즐겨찾기 DELETE는 `movieId` 경로와 HTTP 200/null result를 처리합니다. 날짜 문자열 파싱을 수정하고 409/404는 GET으로 동기화합니다. 쓰기 실패 후에는 재조회부터 수행합니다.
- 영화 목록을 첫 페이지 + 더 보기로 변경했습니다. 추가 로딩 중 카드를 유지하고 실패한 페이지를 다시 요청하며 중복 영화는 제거합니다.
- 검색은 제출 시에만 실행하고 공백 검색을 보내지 않습니다. 검색과 목록은 서로 다른 상태를 사용합니다.
- 장르·검색어 변경 시 이전 상태를 초기화하고 늦은 응답과 dispose 이후 알림을 무시합니다.
- 계정·세션별 Provider key, 401 도메인 코드 판정, 토큰 읽기 중 세션 변경 검사를 적용했습니다.
- 기존 평점 저장 후 중복 GET과 삭제 성공 코드(204)를 수정하고 회귀 테스트의 API 계약과 Provider 구성을 갱신했습니다.
- 기존 코드의 정적 분석 지적 사항을 정리했습니다.

홈의 인기 영화 5개 조회는 유지합니다. Challenge의 debounce, 무한 스크롤, 평점·즐겨찾기 통합 저장은 포함하지 않습니다.

## 검증

- `flutter analyze --no-pub`: 지적 사항 없음
- `flutter test --no-pub`: 전체 45개 테스트 통과
- 페이지 재시도·중복 제거·끝 상태, 검색/장르의 늦은 응답 무시, 일부 카드 실패/재조회, 상세 복귀 목록 갱신 로직, 동시 조회 5개 제한 검증
- 즐겨찾기 409 동기화, 같은 계정의 새 세션 차단, AUTH401_2/3/4 만료와 AUTH401_1/403/회원 없음의 로그인 유지 검증
- TMDB로 MovieLog JWT 미전송, 토큰 읽기 중 로그아웃 시 요청 취소 검증
- 검색·즐겨찾기 라우트의 뒤로가기와 하단 탭 비노출 위젯 테스트

## 트러블슈팅

즐겨찾기 해제 요청이 목록 경로로 body를 보내고 있었고, `createdAt` 문자열을 DateTime 필드에 그대로 넣고 있었습니다. movieId 경로 및 날짜 파싱을 수정하고 서비스 계약 테스트로 확인했습니다. 기존 회귀 테스트에서는 평점 중복 GET, 이전 버전 경로/응답 기대값, Provider 및 GoRouter 누락을 수정했습니다.
